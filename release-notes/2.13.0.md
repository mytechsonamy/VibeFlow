# VibeFlow v2.13.0 — Autonomous-Loop Observability

**Sprint 25.** Sprints 20–24 built a deep autonomous slow loop, but its
activity was scattered across six files. v2.13.0 adds a single pane of
glass — the trust layer the autonomy now needs.

## The audit reader

New read-only `hooks/scripts/loop-audit.sh` consolidates the autonomous
loop's telemetry into one compact JSON summary: per-key
`auto-apply`/`auto-revert`/`auto-apply-held` counts (over the recent
`loopAudit.window` rows) with revert rates, currently cooled-down keys,
the armed revert watch, the learning report's finding count, and the
most recent `learning-apply` decisions. It is fully guarded — every
absent file degrades to zeros, so a fresh project never errors.

## `/vibeflow:status` → Autonomous Loop

A new **Autonomous Loop** section runs the reader and renders it:

- auto-apply tally + **per-key revert rate**, flagging any key at
  `revertRate ≥ 0.5` as a candidate for removal from `autoApply.keys`
  (the same signal the S24-B `auto-tune-ineffective` detector raises);
- cooled-down keys + the armed watch (a tune awaiting next-round
  judgement);
- the learning report's finding count + how to read it;
- the last few auto-apply decisions.

When nothing has happened, the section collapses to a single idle line —
no noise for projects that don't use the autonomous loop.

## Configuration

```jsonc
{ "loopAudit": { "window": 20 } }
```

`window` (int [1, 1000], default 20) bounds how many recent `auto-*`
history rows the per-key tally summarizes. See `docs/LOOP-AUDIT.md`.

## Upgrade

```
/plugin uninstall vibeflow@vibeflow
/plugin install vibeflow@vibeflow
/reload-plugins
```

No migration; the audit is read-only and additive.
