# VibeFlow v2.1.0 — Generic phase enforcement

New feature release. Write and Edit tool calls are now physically
gated by SDLC phase; the days of `/vibeflow:init` scaffolding a test
project during REQUIREMENTS are over.

## The gap v2.1.0 closes

Before this release VibeFlow's only hard phase gate was
`commit-guard.sh` — `git commit` was rejected in phases before
DEVELOPMENT. Every other mutation vector (`Write`, `Edit`, and
file-producing `Bash` calls) flowed through unchecked. Result
observed in the field: `/vibeflow:init` in REQUIREMENTS correctly
produced a brownfield analysis **and then** went on to scaffold a
test project (`src/`, `.cs` files, `dotnet sln add`, new tests), all
of which belong in DEVELOPMENT.

The user reasonably asked: "shouldn't VibeFlow have prevented this?"
This release says yes, and makes that true for all seven phases.

## What changed

### New hook: `phase-write-guard`

`hooks/scripts/phase-write-guard.sh` runs on every `Write` / `Edit`
tool call. It:

1. Reads the target `file_path` from the PreToolUse JSON envelope.
2. Resolves the current phase via `vf_current_phase()` (backend-
   agnostic after Sprint 11-C).
3. Loads `hooks/scripts/phase-policy.json` and glob-matches the
   repo-relative path against the phase's `allow` → `warn` → deny
   ladder.
4. Exits 2 on block (Claude Code surfaces the stderr message);
   exits 0 on allow or warn.

Matcher wired in `hooks/hooks.json` as `matcher: "Write|Edit"`, no
`if:` predicate — the script itself filters by `file_path`.

### Path policy per phase

| Phase | Allowed writes | Warn | Blocked |
|---|---|---|---|
| REQUIREMENTS | `docs/**`, `.vibeflow/**`, `vibeflow.config.json`, `README*`, `*.md` | — | source code, `src/**`, `tests/**` |
| DESIGN | + `design/**`, `*.figma`, `wireframes/**`, `*.css`, `*.scss` | — | source |
| ARCHITECTURE | + `contracts/**`, `.vibeflow/reports/adr-*.md`, `*.d.ts` | — | business logic |
| PLANNING | + `docs/sprints/**` | — | source |
| DEVELOPMENT | everything (`**`) | — | — |
| TESTING | `**/*.test.*`, `**/*.spec.*`, `tests/**`, `test/**`, docs, `.vibeflow/**` | `src/**` non-test | — |
| DEPLOYMENT | `CHANGELOG*`, `release-notes/**`, `.github/workflows/**`, `Dockerfile*`, docs | `src/**` | — |

`.vibeflow/**` + `vibeflow.config.json` are always allowed so the
framework never self-blocks. The integration harness
`tests/integration/sprint-13.sh [S13-A]` pins that invariant.

### Skill Phase Contracts

Five high-risk skills now carry a "Phase Contract" block at the top
of their `SKILL.md` bodies, instructing Claude to read
`vibeflow.config.json.currentPhase` and refuse to run outside the
allowed set:

| Skill | Allowed phases |
|---|---|
| `init` | REQUIREMENTS |
| `test-strategy-planner` | PLANNING |
| `component-test-writer` | DEVELOPMENT, TESTING |
| `coverage-analyzer` | TESTING |
| `release-decision-engine` | DEPLOYMENT |

The contracts are belt-and-suspenders on top of the hook — the hook
stops writes, the contracts stop the analysis logic that would
otherwise produce stale/invalid reports (e.g. `coverage-analyzer`
running mid-DEVELOPMENT against a partial suite).

### Init skill fix

`skills/init/SKILL.md` was the canonical offender. Sprint 13-D:

- Step 1 no longer asks for `mode: solo/team` (Sprint 11-E removed
  that from the manifest; the skill was stale).
- Step 2 config template no longer carries `"mode"`.
- Step 4 ("Detect Existing Codebase") is analysis-only — one file
  under `.vibeflow/reports/`, no `mkdir src/`, no test scaffold, no
  `git add`/`git commit`, no `dotnet sln add`.
- Step 5 closes with "Now run `/vibeflow:prd-quality-analyzer`".
- New Phase Contract at the top.

### Escape hatches

- `VF_ALLOW_PHASE_WRITE=1 <tool>` — per-call override for an
  emergency.
- Missing `hooks/scripts/phase-policy.json` → fail-safe allow
  (framework never bricks an install).
- Missing `python3` → fail-safe allow (matcher needs python).

`docs/PHASE-BOUNDARIES.md` has the full reference + troubleshooting.

## Upgrade

```bash
claude plugin marketplace update vibeflow
claude plugin install vibeflow@vibeflow
```

Expect to see `phase-write-guard` blocks on any stale session
trying to write source code pre-DEVELOPMENT. Run
`/vibeflow:advance` to progress, or use the escape hatch for
one-shot overrides.

No state-format change. No data migration needed.
