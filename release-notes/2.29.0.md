# VibeFlow v2.29.0 — DEVELOPMENT actually runs (analyzers invocable + a robust diff)

Two bugs from a live AntOS DEVELOPMENT walk, fixed together.

## Fixed: phase-runner couldn't run its own analyzers

`quality-gates` (DEVELOPMENT), and `release-decision-engine` + `deploy-verifier`
(DEPLOYMENT) are **auto-satisfy analyzers** — mechanical skills that run a check
and satisfy a phase exit criterion. `quality-gates`'s own description says it
exists to unblock "DEVELOPMENT → TESTING advance **without manual MCP calls**."
But all three were marked **`disable-model-invocation: true`**, which makes a
skill un-forkable — so `phase-runner` *couldn't* run them, and the operator had
to run the lint/typecheck/tests (or the release decision) by hand.

Removed `disable-model-invocation: true` from all three. They now run as part of
the automated walk. The human stays in control the right way: the
GO/CONDITIONAL/BLOCKED decision is visible, every phase still gates on
`consensus.<phase>.approved`, and the actual deploy is a separate manual action.

(This is the same misconfiguration class as the v2.26.0 `agent: Explore` fix —
skills mis-tagged so phase-runner couldn't execute them.)

## Fixed: the DEVELOPMENT diff crashed and under-reviewed

phase-runner's DEVELOPMENT primary was a hardcoded `git diff HEAD~1..HEAD`. That:

- **exits 128** when the project isn't a git repo, or has fewer than two
  commits (`HEAD~1` doesn't exist — exactly what a fresh "Sprint 0" repo hits);
- only reviews the **last commit**, even though a DEVELOPMENT increment usually
  spans several commits (sprints / slices).

Step 2 now resolves the base robustly:

1. guard that it's a git repo (else a clear breadcrumb, not a crash);
2. prefer the **merge-base with the default branch** — so the *whole increment*
   on the feature branch is reviewed, not just the last commit;
3. fall back to `HEAD~1` (≥2 commits), then to the **empty tree** (so the very
   first commit is reviewable).

`git diff <base>..HEAD` no longer crashes, and the AI review + `quality-gates`
see the full increment.

Pinned by `tests/integration/sprint-41.sh` — the three analyzers are invocable,
plus a runtime probe of the base resolver across single-commit, two-commit, and
non-git repos.
