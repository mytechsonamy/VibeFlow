# VibeFlow v2.31.0 — analyzers arm consensus only when they pass

A live AntOS TESTING run surfaced a self-defeating loop in the consensus gate.

## The problem

`coverage-analyzer` and `mutation-test-runner` wrote the consensus marker
(`.vibeflow/state/consensus-needed.json`) **unconditionally** as their last
step — even when the run **failed** (coverage under threshold, a P0 mutant
survived, or no mutation runner installed). `consensus-gate` then blocks every
following `Bash|Write|Edit` until consensus runs. So a *failing* analyzer
blocked the exact work you needed to do to **make it pass** — write the missing
tests, install Stryker, re-run coverage.

The operator's only escape was to set `VF_SKIP_CONSENSUS_GATE=1` and `rm` the
marker by hand on nearly every command — which trains you to bypass the gate
entirely and defeats its purpose.

## The fix: arm-on-pass

Both analyzers now arm the consensus marker **only when `VERDICT == "PASS"`**.

- **Failing / blocked run** → no marker. The analyzer emits an advisory naming
  the gap (the uncovered P0 lines, the surviving mutant, the missing runner) and
  a `▶ Next:` breadcrumb, and leaves the gate clear so you can iterate freely.
- **Passing run** → arms the marker as before. Consensus then reviews a *ready*
  artifact (the passing coverage + mutation reports), which is its actual job.

This matches the precedent already set by `quality-gates`, which is
intentionally marker-less. The marker schema is unchanged on the PASS path, so
nothing downstream changes — you just stop fighting the gate while you're still
getting to green.

Pinned by `tests/integration/sprint-43.sh`. sprint-18 / sprint-19 (marker schema
+ auto-satisfy) stay green.
