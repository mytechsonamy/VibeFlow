# VibeFlow v2.5.4 — Orchestrator auto-records consensus + PRD analyzer auto-satisfies criteria

Closes the last manual step. After this release, the chain from
PRD analysis → consensus → phase advance works end-to-end
without the operator calling `sdlc_record_consensus` or
`sdlc_satisfy_criterion` by hand.

## What changed

### Orchestrator auto-records consensus

`skills/consensus-orchestrator/SKILL.md` gains **Step 3c.0**:
right after the aggregator finalises the verdict, the orchestrator
calls:

```
mcp__sdlc-engine__sdlc_record_consensus {
  "projectId": "<from vibeflow.config.json>",
  "phase":     "<currentPhase>",
  "status":    "<APPROVED | NEEDS_REVISION | REJECTED | HUMAN_APPROVAL_REQUIRED>",
  "agreement": <verdict.json .agreement>,
  "criticalIssues": <verdict.json .criticalTotal>
}
```

This writes `lastConsensus: {phase, status, agreement,
criticalIssues, recordedAt}` into `project.json`. The validator's
scope check for `consensus.<phase>.approved` reads it on the next
`/vibeflow:advance`.

Without the auto-record (v2.5.3 and earlier) the validator saw
`lastConsensus: null` and blocked advance even after a clean
APPROVED verdict — exactly the symptom FlowBridge_TR hit.

### PRD analyzer auto-satisfies REQUIREMENTS criteria

`skills/prd-quality-analyzer/SKILL.md` now calls:

```
mcp__sdlc-engine__sdlc_satisfy_criterion {
  "projectId": "<from config>",
  "criterion": "prd.approved"
}
```

unconditionally after writing the quality report, plus:

```
mcp__sdlc-engine__sdlc_satisfy_criterion {
  "projectId": "<from config>",
  "criterion": "testability.score>=60"
}
```

**only when the measured testability score is ≥ 60**. Below
threshold, the gate correctly keeps REQUIREMENTS → DESIGN blocked
until the PRD improves.

### Graceful degradation

If the MCP tool isn't reachable (sdlc-engine server unavailable,
paths still broken, etc.), both skills emit a visible
"sdlc-engine MCP unavailable — satisfy manually:" hint and
continue. The verdict.json + quality report remain the source of
truth on disk; only the state registration is skipped.

## FlowBridge_TR end-to-end walkthrough

After upgrading to v2.5.4 and restarting Claude Code, the flow is:

```
1. /vibeflow:prd-quality-analyzer docs/FlowBridge_TR_SRS_v1_1.docx
   → writes report + cost-avoidance doc
   → auto-calls sdlc_satisfy_criterion for prd.approved
   → auto-calls sdlc_satisfy_criterion for testability.score>=60 (score=63)
   → writes consensus-needed.json marker

2. Consensus-gate hook blocks the next Bash/Write/Edit call →
   prompts: "RUN THIS NEXT: /vibeflow:consensus-orchestrator …"

3. /vibeflow:consensus-orchestrator .vibeflow/reports/prd-quality-report.md
   → 3 reviewers (claude + codex + gemini) review across ≤5 rounds
   → aggregator writes verdict.json (APPROVED in your prior run)
   → auto-calls sdlc_record_consensus → lastConsensus registered

4. /vibeflow:advance
   → reads currentPhase=REQUIREMENTS, next=DESIGN
   → validator passes: prd.approved ✓, testability.score>=60 ✓,
     consensus.requirements.approved (via lastConsensus) ✓
   → advances REQUIREMENTS → DESIGN
   → writes phase_advanced event (with humanOverrideNote if
     status was HUMAN_APPROVAL_REQUIRED)
```

No manual MCP tool calls required.
