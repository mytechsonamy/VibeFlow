# VibeFlow v2.17.0 — phase-runner TESTING Auto-Run

**Sprint 29** (backlog B5). `/vibeflow:phase-runner` was a one-command
walk for every phase *except* TESTING. The gap: `coverage-analyzer`
**parses** an existing coverage JSON — it doesn't run the suite to
produce one — so a TESTING walk needed the operator to generate coverage
by hand first. v2.17.0 closes it: phase-runner now generates the coverage
artifact itself, making TESTING a true one-command walk.

## The generate step

In **TESTING only**, before forking the analyzers, phase-runner runs the
project's coverage command (Step 2a), resolved from
`vibeflow.config.json.tech.coverageCommand` or defaulted by
`tech.testRunner`:

| testRunner | default |
|---|---|
| `vitest` | `npx vitest run --coverage` |
| `jest` | `npx jest --coverage` |
| `pytest` | `pytest --cov --cov-report=json` |
| `dotnet` | `dotnet test --collect:"XPlat Code Coverage"` |

(`mutation-test-runner` self-generates its mutants and runs the suite
itself, so it only needs `tech.testCommand` — coverage was the missing
piece.) The step is recorded as `generate:coverage` in the Sprint-21
progress ledger. TESTING is now: **generate coverage → analyze →
consensus → advance**, one command.

## Safe by default

- **Best-effort.** If the coverage command is missing (unknown runner) or
  fails, phase-runner logs it and **continues** — `coverage-analyzer`
  then surfaces the precise missing-coverage block instead of a silent
  failure.
- **Opt-out.** `--no-generate` (or `VF_SKIP_GENERATE=1`) skips the step
  for operators who generate coverage in CI / by hand.
- **TESTING-only.** Every other phase walk is byte-for-byte unchanged.

`phase-runner`'s `allowed-tools` gains the runner binaries (`npm`, `npx`,
`pnpm`, `yarn`, `pytest`, `dotnet`, `cargo`, `go`) — mirroring
`quality-gates`. See `docs/TESTING-READINESS.md`.

## Upgrade

```
/plugin uninstall vibeflow@vibeflow
/plugin install vibeflow@vibeflow
/reload-plugins
```

No migration, no config change required (defaults cover the common
runners; set `tech.coverageCommand` to override).
