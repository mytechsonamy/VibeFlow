# VibeFlow v2.40.0 — phase-runner surfaces in-flight work before progressing

"Run phase-runner" reads, reasonably, as "do what's needed to move forward". But
phase-runner only advances the SDLC *phase* — it doesn't commit or push your
work. An operator hit exactly this gap: they ran phase-runner with a finished but
**uncommitted** change still sitting in the tree, and phase-runner advanced the
phase without flagging it.

Why it matters: going **into DEVELOPMENT**, `code.reviewed` runs consensus on the
**committed** diff. Anything left uncommitted is never part of that review — it
can slip into the increment unreviewed.

## What changed

phase-runner's Step 0 now checks for in-flight work and **names** it before
progressing:

- `git status --porcelain` — uncommitted changes, with a heads-up that they
  **won't be in the DEVELOPMENT review diff** and a `git add/commit` breadcrumb;
- `review-pending.json` — a committed-but-unreviewed change (the
  `trigger-ai-review` marker), named so you know consensus on the diff covers it.

It is deliberately **surface-only**:

- it **never auto-commits** — git stays yours;
- it **never blocks** — you may intentionally leave work uncommitted;
- it **stays quiet** when there's nothing pending.

So "run phase-runner" no longer silently advances past unreviewed in-flight work
— it tells you what's still uncaptured and lets you decide. Pinned by
`tests/integration/sprint-52.sh`.
