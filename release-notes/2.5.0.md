# VibeFlow v2.5.0 — Iterative Consensus + Phase Specialists

**Sprint 17.** Consensus now negotiates across multiple rounds
instead of failing at the first NEEDS_REVISION, critical findings
dedup cross-reviewer so "3 reviewers flag the same thing" counts
as 1 (not 3), and six new phase-specialist subagents can deeply
rewrite artifacts based on reviewer feedback. Closes the
agreement-accounting bug where unanimous NEEDS_REVISION was
falsely escalating to REJECTED.

## Loop shape

```
round=1 …
while round <= consensus.maxIterations (default 5):
    reviewers (codex + gemini + claude-reviewer) review,
    each one reading the previous round's verdicts + top findings

    aggregate → verdict.json.rounds[round-1]

    APPROVED  (agreement ≥ 0.9 + criticalDedup = 0) → break
    REJECTED  (majority rejected OR ≥2 deduped critical) → break
    otherwise → round += 1

if rounds exhausted without convergence:
    if agreement ≥ 0.5, not majority-rejected, no ≥2 critical:
        status = HUMAN_APPROVAL_REQUIRED   # pass-with-audit
    else: stays NEEDS_REVISION / REJECTED per rules
```

## What's new

### Iteration loop (S17-A)

Three new config keys in `vibeflow.config.json`:

```json
{
  "consensus": {
    "maxIterations": 5,
    "approvalThreshold": 0.9,
    "iteration": { "enabled": true }
  }
}
```

All optional — omit any and the default applies. Set
`iteration.enabled: false` to get the pre-2.5.0 single-round
behaviour as a rollback switch.

### Critical finding dedup (S17-B)

The aggregator now recognises two shapes of `criticalIssues`:

**New array shape (Sprint 17+):**
```json
"criticalIssues": [
  {
    "id": "claude-c1",
    "target": { "file": "docs/prd.md", "line_range": [120, 145] },
    "title": "Data residency for BDDK BİSY missing",
    "rationale": "7-year audit logs + muhabir API transit must be..."
  }
]
```

**Legacy integer shape (2.4.0 and earlier):**
```json
"criticalIssues": 3
```

Array form deduplicates cross-reviewer by `{file, line_range}`
equality OR by Jaccard similarity of title words (≥ 0.6 = same
finding). Integer form still sums (no dedup possible) and writes
`criticalRawCount: 0` as an audit signal that no structured items
arrived.

The pre-2.5.0 `agreement < 0.5 → REJECTED` rule is retired.
Unanimous NEEDS_REVISION reviewers now end the round as
NEEDS_REVISION, flow to the arbiter, and can advance to the next
round. Only an explicit majority of REJECTED verdicts (or
≥2 deduped critical findings) now trips REJECTED.

### HUMAN_APPROVAL_REQUIRED status (S17-C)

Fourth consensus status value: **HUMAN_APPROVAL_REQUIRED**. The
orchestrator emits it when `maxIterations` rounds pass without
crossing `approvalThreshold` agreement but the run didn't hit a
hard reject. Pass-with-audit flow:

```
/vibeflow:advance DESIGN humanOverrideNote="YÖS tier resolved offline with Legal"
```

The MCP tool `sdlc_advance_phase` accepts an optional
`humanOverrideNote: string` field. Engine threads it through to
the `phase_advanced` event's payload; the filesystem event log
records it; `load-sdlc-context.sh` surfaces the advisory on
subsequent SessionStart calls:

```
VibeFlow: last phase advance (REQUIREMENTS → DESIGN at 2026-04-21) ran under HUMAN_APPROVAL_REQUIRED.
  Override note: YÖS tier resolved offline with Legal.
```

The line stays visible until a new `phase_advanced` event
without an override supersedes it.

### 6 phase-specialist subagents (S17-D)

Orchestrator's follow-up prose on NEEDS_REVISION or
HUMAN_APPROVAL_REQUIRED now offers two paths:

```
Next options:
  /vibeflow:consensus-arbiter <sid>       — mechanical diff-first patches
  /vibeflow:consensus-specialist <sid>    — deep rewrite by <phase-specialist>
```

Per-phase specialists:

| Phase | Agent | Rewrites |
|---|---|---|
| REQUIREMENTS | `prd-rewriter` | PRD ambiguities, missing flows, conflicts |
| DESIGN | `design-spec-refiner` | a11y gaps, design-token drift, flow states |
| ARCHITECTURE | `adr-author` | new ADRs for contested decisions, arch-doc sections |
| PLANNING | `test-strategy-refiner` | scenario-set expansion, priority reshuffles |
| TESTING | `coverage-gap-filler` | new tests for P0-uncovered paths + surviving mutants |
| DEPLOYMENT | `runbook-editor` | rollback recipes, release-notes gaps, runbook health checks |

All agents run `context: fork` + `model: opus` + `effort: high`,
share the same diff-first contract (never writes to source
directly), and emit exactly one unified-diff patch + one
decision report per invocation.

### Dispatcher skill (S17-E)

`/vibeflow:consensus-specialist [<session-id>]` reads the
current phase from `vibeflow.config.json`, forks the matching
specialist agent, and routes the patch into the session's
manifest with `type: "specialist"`. `apply-arbiter-patch`
processes arbiter + specialist patches in order.

Only one specialist per session — a second invocation without
`--force` refuses to run (two deep rewrites on the same verdict
= conflicting patches).

## Upgrade notes

- **Existing consensus sessions stay valid.** The round-aware
  aggregator defaults to round=1 when no marker exists. Legacy
  single-reviewer sessions keep writing the old verdict shape
  with the new `rounds: [{round:1, …}]` wrapper.
- **Reviewer output compatibility.** Reviewers emitting the old
  integer `criticalIssues` shape still work (fallback path +
  audit warning). New reviewers should emit the array form to
  benefit from dedup.
- **`consensus.quorum`** (Sprint 14) still honoured — unchanged.
- **`VF_SKIP_AUTO_CONSENSUS=1`** (Sprint 15) and
  `VF_SKIP_CONSENSUS_GATE=1` (Sprint 16) still work — unchanged.

## Backward compatibility

- Single-round sessions continue to work byte-compatibly. The
  aggregator defaults to round=1 when the marker is absent,
  uses the original epoch-suffix archive name, and writes
  verdict.json with `finalRound: 1` + `rounds: [{round:1, …}]`.
- Legacy integer `criticalIssues` still parses; the aggregator
  sums (no dedup possible) and records `criticalRawCount: 0` so
  downstream auditors can see the legacy path ran.
- HUMAN_APPROVAL_REQUIRED is additive — callers that only
  accept APPROVED (non-phase-gate code paths) continue to reject
  it as before. Only the `validation.ts` gate + the event log
  carry the new status end-to-end.
