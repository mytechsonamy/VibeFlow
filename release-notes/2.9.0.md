# VibeFlow v2.9.0 — Signal-Quality Refinement

**Sprint 21.** The consensus loop has been mechanically complete since
v2.8.0. v2.9.0 sharpens three of its coarse inputs/outputs — what
reviewers *see*, what memory *keeps*, and what the operator *sees* — with
no new loop mechanics.

## Semantic primary-artifact excerption (S21-A)

When a primary exceeds `consensus.excerptTokenBudget` (default 30k
tokens), `consensus-orchestrator` used to feed reviewers the first 40% +
last 15% — positional, so the most-contested middle section was dropped.
v2.9.0 makes excerption **relevance-based** (`consensus.excerptStrategy:
"semantic"`, default): the doc is split into sections and each is scored
by **evidence-finding density + reviewer-memory hits + evidence-keyword
overlap**. The first section is always included; the budget fills with
the highest-scored sections in document order. Falls back to the legacy
head/tail (`"headtail"`) when a doc has no section structure — never
worse than before. Scoring is lexical (deterministic); see
`docs/EXCERPTION.md`.

## Theme-aware reviewer-memory compaction (S21-B)

Sprint 20 reviewer memory was pure recency — a critical raised 6 rounds
ago aged silently out of the cap. v2.9.0 adds
`reviewerMemory.compaction: "theme-aware"` (default): when an entry is
dropped past the cap, its criticals fold into a per-artifact recurrence
summary with a `seenCount` (Jaccard title match), and
`consensus-orchestrator` surfaces **recurring criticals first** in the
`PRIOR REVIEW MEMORY` block — a long-standing objection leads, so
reviewers escalate it. `"recency"` restores the old drop-silently
behaviour. See `docs/REVIEWER-MEMORY.md`.

## Phase-runner progress ledger (S21-C / S21-D)

`phase-runner` was invisible mid-run. v2.9.0 writes a structured ledger
to `.vibeflow/state/phase-runner-progress.json` (phase, steps[],
currentStep, attempt N/max, terminal status), updated at every step
boundary. `/vibeflow:status` renders a **Phase-Runner Progress** section
from it, with a stale-guard that ignores a ledger from a different phase
or a finished-and-advanced run. Not an interactive TUI — a ledger +
on-demand render, the realistic surface for a prose+bash skill. See
`docs/PROGRESS-LEDGER.md`.

## Configuration

```jsonc
{
  "consensus":      { "excerptTokenBudget": 30000, "excerptStrategy": "semantic" },
  "reviewerMemory": { "compaction": "theme-aware" }
}
```

All additive and fully defaulted — an empty `vibeflow.config.json`
behaves identically to a fully-specified one.

## Upgrade

```
/plugin uninstall vibeflow@vibeflow
/plugin install vibeflow@vibeflow
/reload-plugins
```

No migration. Excerption defaults to semantic-with-headtail-fallback;
memory defaults to theme-aware (a recency store simply gains no summary
row until its first overflow); the ledger is additive.
