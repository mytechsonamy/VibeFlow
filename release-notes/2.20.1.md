# VibeFlow v2.20.1 — apply-arbiter-patch gets a real rollback safety net

A patch release prompted by a real AntOS run: the specialist produced a
PRD rewrite, and `/vibeflow:apply-arbiter-patch` was about to apply it —
but AntOS isn't a git repo, so the skill's only documented rollback
(`git checkout HEAD -- <file>`) had nothing to restore from. Applying would
have rewritten the PRD in place with no way back.

## Fixed

`apply-arbiter-patch` now takes a **git-independent snapshot before it
applies anything** (new Step 3.5):

- Every target file (the unique list from the diff preview) is copied to
  `.vibeflow/state/arbiter-backups/<session>/` before the first `git apply`.
- The skill prints the restore command up front:
  `cp -R .vibeflow/state/arbiter-backups/<session>/. .`
- This is now the **primary** rollback path — it works whether or not the
  project is a git repo. `git checkout HEAD -- <file>` remains as the
  secondary path for committed git repos.

Why it matters: REQUIREMENTS-phase projects are frequently just a PRD with
no repo yet (or an uncommitted doc). The specialist→apply loop edits that
artifact in place; without a snapshot, a bad rewrite was unrecoverable.

No behavior change to the apply itself, the diff preview, the `--yes` /
`--dry-run` / `--run-tests` flags, or the Sprint 19-E auto-chain. Purely an
additive safety net. Pinned by `tests/integration/sprint-15.sh [S15-G]`.
