# VibeFlow v2.0.2 — Manifest schema fix

Hotfix over v2.0.1. `claude plugin install vibeflow@vibeflow` was
rejecting the manifest with:

```
✘ Failed to install plugin "vibeflow@vibeflow":
Plugin has an invalid manifest file at .claude-plugin/plugin.json.
Validation errors: repository: Invalid input: expected string,
received object
```

## Root cause

`.claude-plugin/plugin.json` carried `repository` and `bugs` as npm-
style `{ type, url }` objects. Claude Code's plugin loader validates
these fields as strings (per the [plugins reference](https://code.claude.com/docs/en/plugins-reference.md))
and refuses to install.

## Fixed

- `repository` and `bugs` are now plain URL strings.
- `homepage` / `repository` URLs corrected from the stale
  `mustiyildirim/vibeflow` slug to the actual `mytechsonamy/VibeFlow`
  repo.
- `tests/integration/sprint-4.sh` updated to assert the string-form
  schema — this was the test that was (incorrectly) pinning the bad
  object form. If you were testing against v2.0.0 or v2.0.1 locally,
  `sprint-4.sh` 351/351 now.

## Upgrade

```bash
claude plugin marketplace update vibeflow
claude plugin install vibeflow@vibeflow
```

If you've already registered the marketplace via
`claude plugin marketplace add mytechsonamy/VibeFlow`, no re-add is
needed — `update` refreshes the clone to the new tag.

No behaviour change, no data migration. Install should complete in
seconds as advertised in the v2.0.1 notes.
