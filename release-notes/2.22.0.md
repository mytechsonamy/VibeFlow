# VibeFlow v2.22.0 — the DESIGN phase gets a guide (Claude-native or Figma)

DESIGN was the one SDLC phase VibeFlow couldn't help with: a design has to be
*authored* before it can be reviewed, and there was no skill for that —
`phase-runner` just said "operator writes design, then I run consensus on
`design/`." For a product where the UI matters, that's a gap.

## Added: `/vibeflow:design-bootstrap`

The DESIGN-phase author-side guide. It turns the approved PRD into the
artifacts DESIGN consensus reviews, and — **every run, no forced default** —
asks you which design source to use:

| Source | What it does | Needs |
|---|---|---|
| **Claude-native** | Generates an attractive, accessible UI spec + a real design-token system (semantic palette + dark mode, type/spacing scale) + wireframes from the PRD, tuned to your domain | nothing |
| **Figma (existing file)** | Pulls your Figma file via VibeFlow's `design-bridge` MCP → `design-tokens.json` + `styles.css` + a spec referencing your frames | `FIGMA_TOKEN` + URL |
| **Figma (from scratch)** | Designs from scratch in Figma via the **official** Figma MCP (`use_figma`) against a design system, then syncs back | the Figma MCP connected |

Whichever you pick, the output is the same: real files under `design/`
(`design-spec.md` is the primary the panel reviews) + tokens + evidence. Then
it arms the consensus marker and emits `▶ Next: /vibeflow:phase-runner` (which
runs cross-AI consensus on the spec and advances on APPROVED). `design.approved`
+ `accessibility.verified` stay operator-confirmed — a human signs off the look
and the a11y pass.

The Claude-native path is deliberately not a bland skeleton: it produces a real
design system (semantic colors with dark mode, a type + spacing scale,
per-screen layouts with **all states** — empty/loading/error/success — responsive
rules, and a concrete WCAG 2.2 AA accessibility section), domain-tuned (e.g.
calm + high-legibility for `financial`). You can hand the spec + tokens to a
designer later, or drive it straight into DEVELOPMENT.

## Connecting Figma

Two independent paths, your choice:

- **Existing file (`design-bridge`):** create a Figma personal access token
  (File content: read), set the plugin's `userConfig.figma_token` (→ the
  `FIGMA_TOKEN` env the MCP reads — never hardcoded), restart, and paste your
  file URL (saved to `design.figmaFileUrl`). VibeFlow extracts tokens + styles.
- **From scratch (official Figma MCP):** connect the Figma MCP and let
  `use_figma` generate the screens against your design system.

Full guide: **`docs/DESIGN-PHASE.md`**.
