# VibeFlow v2.20.0 — command-collision audit + `status` → `flow-status`

A follow-up to v2.19.0's `init` → `onboard` rename. An operator hit the
**same class of bug** trying to run Claude Code's built-in `/status` (to
check usage/quota) — VibeFlow's `status` skill shadowed it in the command
picker. So we audited *all* skills against the built-ins and fixed the one
remaining collision.

## ⚠️ Breaking: `/vibeflow:status` → `/vibeflow:flow-status`

VibeFlow's project-status skill was named `status`, colliding with the
built-in `/status`. It is now **`/vibeflow:flow-status`** — same output
(SDLC phase, pending tasks, quality metrics, autonomous-loop section), new
name. No shim (a lingering `status` would re-create the collision). Update
any muscle memory / scripts.

## The audit

All **41 skills** were checked against Claude Code's built-in slash command
set. After the v2.19.0 `init`→`onboard` rename, `status` was the **only
remaining exact collision**. Post-v2.20.0: **zero exact collisions**.

`loop-status` was reviewed and **kept** — it's a distinct name; `/loop`
matches the built-in exactly, only a fuzzy search surfaces it. The full
study (table + the policy for naming future skills so this doesn't recur)
is in the new [docs/COMMAND-COLLISIONS.md](../docs/COMMAND-COLLISIONS.md).

## Also fixed

- CLAUDE.md's Key Commands listed a stale `/vibeflow:review` (no such
  skill). Replaced with `/vibeflow:consensus-orchestrator`, the actual
  multi-AI review trigger.

## Compatibility

- Pure rename + doc cleanup; no behavior, schema, or consensus-flow change.
- 36 live references (`phase-runner`, `loop-status`, `advance`, the
  status/loop-audit hooks, docs) were repointed; historical release-notes
  and `docs/SPRINT-*.md` left intact. `tests/integration/sprint-32.sh`
  pins rename completeness.
