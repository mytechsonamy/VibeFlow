# VibeFlow v2.0.1 — Bundled MCP servers (install-hang fix)

**Packaging fix. No behavioural change from 2.0.0.** If your 2.0.0
install completed, upgrading is optional.

## What hung

`claude plugin install vibeflow@vibeflow-local` was hanging for
minutes (or indefinitely, under iCloud-synced filesystems) on
`Installing plugin…`. Root cause: Claude Code's marketplace
`source: directory` type is a **naive recursive copy** of the plugin
directory into `~/.claude/plugins/cache/temp_local_<ts>/`. For a
developer clone of VibeFlow that had run `npm install`, this meant
copying ~500 MB of `node_modules` across the five MCP servers before
the install could complete.

There is no `.claudeignore`, no `files`-whitelist, and no
`.gitignore` respect — the copy is unconditional. Marketplace docs
confirm the only way to avoid copying `node_modules` is to either
(a) not have it on disk, or (b) register the marketplace via a git
source so Claude does a shallow clone instead of a directory copy.

## What we changed

### Every MCP server is now bundled

Each of `sdlc-engine`, `codebase-intel`, `design-bridge`, `dev-ops`,
and `observability` now produces a `dist/bundle.js` (~620-690 KB)
alongside the standard `tsc` output. The bundle is an esbuild
single-file build with all npm deps inlined (`@modelcontextprotocol/sdk`,
`proper-lockfile`, `zod`, etc.), so the plugin runtime no longer
needs `node_modules` to boot any server.

Build command lives in each MCP's `package.json`:
```
tsc && esbuild dist/index.js --bundle --platform=node --format=esm
  --outfile=dist/bundle.js
  --banner:js="import { createRequire } from 'module';
    const require = createRequire(import.meta.url);"
```

`.mcp.json` routes all five servers through `dist/bundle.js`. The
plugin's runtime footprint is now ~3.2 MB total.

### Recommended install flow switched to `github:` marketplace source

[GETTING-STARTED.md](./docs/GETTING-STARTED.md) now leads with:

```bash
claude plugin marketplace add github:mytechsonamy/VibeFlow
claude plugin install vibeflow@vibeflow
```

Claude resolves `github:` marketplaces via a shallow `git clone`
(not a directory copy) — untracked files (including `node_modules`)
are never transferred. End users get a ~3 MB install that completes
in seconds.

Local-dev `--plugin-dir <path>` remains the right path for people
iterating on the plugin itself; `claude plugin marketplace add <path>`
is explicitly advised against for local development because the
recursive copy still happens.

to `dist/bundle.js`. Both artifacts ship in the tarball.

## Upgrade

If you're on 2.0.0 and the install completed:
```bash
claude plugin marketplace update vibeflow
claude plugin install vibeflow@vibeflow          # upgrades in place
```

If you're on 2.0.0 and the install hung:
```bash
claude plugin marketplace remove vibeflow-local
rm -rf ~/.claude/plugins/cache/temp_local_*       # reclaim disk
claude plugin marketplace add github:mytechsonamy/VibeFlow
claude plugin install vibeflow@vibeflow
```
