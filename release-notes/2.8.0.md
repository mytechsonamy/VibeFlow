# VibeFlow v2.8.0 — Close the L3 Learning Loop

**Sprint 20.** VibeFlow's fast loop (per-run consensus) has been
complete since v2.7.0. v2.8.0 builds the **slow loop**: the
L3 Truth-Evolution layer that looks across *time* instead of a
single run. Consensus telemetry that has been accumulating on disk
since Sprint 17 is finally read — to detect structural review drift,
and to give reviewers memory of what they already raised.

## The problem: telemetry written, never read

Every consensus round already persisted per-session jsonl + a
`verdict.json` with a `rounds[]` agreement curve, and every arbiter
run persisted a patch manifest. Nothing consumed any of it. And every
review round started cold — a reviewer re-raised issues it had raised
last round (or last sprint) with no memory of whether they were
resolved.

## Durable consensus history (S20-A)

`consensus-aggregator.sh` now appends one compact **verdict row** per
finalised round to a cross-session roll-up
`.vibeflow/state/consensus/history.jsonl`:

```json
{ "type": "verdict", "sessionId": "…", "phase": "REQUIREMENTS",
  "primaryArtifact": "docs/PRD.md", "round": 2, "status": "NEEDS_REVISION",
  "agreement": 0.78,
  "counts": { "approved": 1, "needsRevision": 2, "rejected": 0, "critical": 2 },
  "reviewers": [ { "name": "codex", "verdict": "NEEDS_REVISION", "critical": 1 } ],
  "suggestionThemes": ["ambiguity"], "timeout": false, "recordedAt": "…" }
```

`apply-arbiter-patch` appends an `arbiter-decision` row per run. The
roll-up is append-only and **idempotent** by `{sessionId, round}`.
`consensus-orchestrator` writes a `<sid>.primary.txt` sidecar so the
aggregator (a SubagentStop hook) can resolve what the panel reviewed.

## Mining it (S20-B / S20-C)

`learning-loop-engine` gains a fourth mode, `consensus-history`,
emitting `.vibeflow/reports/consensus-learning-report.md`. Six
detectors, each gated by the universal ≥ 3-observation floor:
`slow-converging-phase`, `reviewer-skew`,
`recurring-suggestion-theme`, `convergence-stall`,
`primary-artifact-churn`, and the S20-C **effectiveness trace**
(`ineffective-theme`) — which joins an applied theme at round R against
the agreement delta at round R+1 and flags themes that never move the
needle. Stops the loop grinding on cosmetic fixes while the real
objection stands. See `docs/LEARNING-LOOP.md`.

## Cross-session reviewer memory (S20-D / S20-E)

The same finalize step appends a bounded entry (top-3 critical titles)
to `.vibeflow/state/consensus/reviewer-memory/<reviewer>.jsonl`, capped
to `reviewerMemory.maxEntriesPerArtifact` (default 5) per
`(reviewer, artifact)`. Before each round, `consensus-orchestrator`
prepends a `PRIOR REVIEW MEMORY` block to that reviewer's prompt —
"you raised X before; verify it was addressed, don't re-raise resolved
items, escalate recurrences." Bounded by `reviewerMemory.tokenBudget`
(default 600). On a clean first run the block is omitted entirely, so
round-1 prompts are byte-identical to pre-Sprint-20. See
`docs/REVIEWER-MEMORY.md`.

## Polish (S20-F / S20-G)

- **S20-F** — `consensus-gate.sh` now names the **primary artifact**
  (the PRD/ADR under review) in its block message via
  `.primaryArtifact // .artifact`, instead of the analyzer's evidence
  report. Legacy markers fall back cleanly.
- **S20-G** — `decision-recommender` consumes
  `consensus-learning-report.md` as a first-class findings source; a
  `consensus.*` recommendation auto-detects as a `gate-adjustment`
  decision type.

## Configuration

Two new typed config blocks (`mcp-servers/sdlc-engine/src/config.ts`),
both fully defaulted and partial-merge friendly:

```jsonc
{
  "learningLoop":   { "enabled": true, "sprintWindow": 3, "minObservations": 3 },
  "reviewerMemory": { "enabled": true, "maxEntriesPerArtifact": 5, "tokenBudget": 600 }
}
```

`reviewerMemory.enabled: false` is a full rollback switch — the
aggregator stops appending and the orchestrator stops injecting.

## Upgrade

```
/plugin uninstall vibeflow@vibeflow
/plugin install vibeflow@vibeflow
/reload-plugins
```

No config migration needed. History + memory are additive; absent
files ⇒ no rows, no block, and consensus behaves exactly as in v2.7.0.
