# VibeFlow v2.20.3 — balanced JSON extraction for codex 0.135.0

v2.20.2 fixed "reviewer rationale lost to prose-wrapped JSON" — but only for
the *single*-object shape. A live AntOS run found it still fails on **codex
CLI 0.135.0**, which is exactly the version in the field.

## Root cause (the half v2.20.2 missed)

codex `exec` mode (0.135.0) prints the verdict JSON **twice** — once in the
body, once as a trailing echo — with a `tokens used\n20,379` line wedged
between:

```
{ "verdict": "NEEDS_REVISION", "criticalIssues": [...], "suggestions": [...] }
tokens used
20,379
{ "verdict": "NEEDS_REVISION", ... }
```

v2.20.2's `vf_extract_json` grabbed a **greedy** first-`{`…last-`}` span, so
it captured *both* objects **plus** the `tokens used` junk between them →
invalid JSON → jq rejected it → it fell back to keyword grep, which recovered
only the word `NEEDS_REVISION` and threw away codex's `criticalIssues`,
`suggestions`, and rationale. Net result: every round, codex = NEEDS_REVISION
with 0 criticals / 0 suggestions / empty rationale — a real verdict stripped
of all actionable content, so the specialist→apply loop ran blind and the
panel never converged.

## Fix

Replaced the greedy span with a **balanced-brace first-object extractor**
(`_vf_first_json_object`) — an awk state machine that counts `{`/`}` depth
while ignoring braces inside JSON string values and handling escapes, and
emits the **first complete** `{…}` object. So codex's first verdict object is
taken cleanly, duplicate trailer and `tokens used` line ignored.

Verified against:
- codex 0.135.0 duplicate-object output → rationale captured ✓
- Markdown ```` ```json ```` fence (the v2.20.2 case) → still works ✓
- pure JSON → unchanged ✓
- pure prose → keyword-grep fallback ✓
- braces inside string values (`"rationale": "no {x} bounds"`) → handled ✓

Fixed in both `consensus-run.sh` (headless) and the `consensus-orchestrator`
prose (interactive 3-AI). Pinned by `tests/integration/sprint-31.sh [S31-C]`
with a duplicate-object runtime probe.

## Practical effect

codex dissents now carry their findings into the jsonl → reviewer-memory →
the specialist, so the convergence loop can actually act on them. If you were
seeing codex stuck at NEEDS_REVISION with no rationale, update to 2.20.3 and
re-run consensus.
