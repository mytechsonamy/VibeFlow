# VibeFlow v2.20.4 — skip codex's echoed schema template

The third and (verified) final piece of the "codex gives no rationale" saga.
v2.20.2 unwrapped fenced JSON; v2.20.3 handled codex 0.135.0's duplicate
object; v2.20.4 handles its **prompt echo** — diagnosed in a live AntOS run.

## Root cause

`consensus-run.sh` captures codex with `2>&1` (stderr merged into stdout).
codex `exec` echoes the review prompt back, and that prompt contains the JSON
**schema template** the reviewer is told to match:

```
{verdict:APPROVED|NEEDS_REVISION|REJECTED, score:0-100,
 criticalIssues:[{id, target:{file, line_range:[s,e]}, title, rationale}], …}
```

That template is the **first** balanced `{…}` object in the merged stream —
but it's **invalid JSON** (unquoted keys, `|`, `0-100`). v2.20.3's extractor
took the *first* balanced object, hit the template, failed `jq`, and fell back
to keyword grep — discarding codex's real `criticalIssues` + `suggestions`
(0/0) deterministically, every run.

So codex looked content-free — but it never was. Once parsed correctly its
verdict was **score 82, NEEDS_REVISION, 2 critical compliance gaps + 5
suggestions** (e.g. "phase roadmap ships regulated advisory features without a
hard license/partner phase gate", "sample AI responses read as personalized
investment advice without guardrail framing"). The parser was hiding
substantive, financial-domain-appropriate objections.

## Fix

`vf_extract_json` now walks **every** top-level balanced object
(`_vf_json_objects`, FS-delimited) and returns the **first that is valid JSON
with a `.verdict` key** — skipping the echoed schema template and any
non-verdict object, and still handling the duplicate trailer.

Verified against: the prompt-echo + schema-template + duplicate-trailer shape
(recovers 2 criticals / 5 suggestions), the Markdown fence (v2.20.2 case),
pure JSON, pure prose, and braces-in-strings. Fixed in both `consensus-run.sh`
and the `consensus-orchestrator` prose. Pinned by
`tests/integration/sprint-31.sh [S31-C]` with a prompt-echo runtime probe.

## Practical effect

codex's compliance objections now reach the jsonl → reviewer-memory → the
specialist, so the specialist→apply chain finally has codex's real suggestions
to rewrite against. Update to 2.20.4 and re-run consensus; the loop is no
longer blind.
