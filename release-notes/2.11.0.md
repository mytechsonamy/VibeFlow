# VibeFlow v2.11.0 — Bounded Auto-Apply with Auto-Revert

**Sprint 23.** Sprint 22's `learning-apply` was propose-only — every
config tune needed an operator `--yes`. v2.11.0 lets the slow loop go
autonomous **for tunes you trust**, without giving up the safety that
made propose-only the default.

## Opt-in, allowlisted, auto-reverting

`learningApply.autoApply` is **off by default** — a project that doesn't
opt in behaves exactly as in v2.10.0. When enabled, a config-tune finding
auto-applies **only if its key is in `autoApply.keys`** and it clears
every Sprint 22 gate (evidence floor, `maxRelativeStep` clamp,
`EngineConfigSchema` re-validation — the auto path skips none of them).
The auto path:

1. **snapshots** `vibeflow.config.json` to `.vibeflow/state/auto-apply/<ts>/`,
2. `git apply`s the tune with no prompt (`Applied: auto`),
3. **arms a revert watch** with the pre-change baseline agreement.

Keys off the allowlist — and all source/template changes — stay
operator-confirmed.

## Auto-revert on regression

The next consensus round judges the tune. `consensus-aggregator.sh` —
right after it finalises that round's agreement — evaluates the watch:
if the same `{phase, primaryArtifact}` round's agreement dropped by more
than `regressionDelta` (default 0.05) below the baseline, it **restores
the snapshot**, appends an `auto-revert` row to `history.jsonl`, logs to
`.vibeflow/reports/auto-apply-reverts.md`, and arms a **cooldown** so the
key can't immediately re-tune and flap. If agreement held or improved,
the tune is kept ("AUTO-APPLY HELD"). The only config write the
aggregator ever makes is a restore to a known-good snapshot — and with no
watch armed (the default), it's a no-op.

## Why this is safe to automate

The slow loop tunes the machinery that governs quality gates — the danger
is a tuner that quietly drifts a gate looser ("gate-suppression-creep",
the very thing the learning loop exists to catch). Auto-revert is the
answer: a tune that makes consensus *worse* is undone automatically and
cooled down, so the loop can only keep changes that *improve* agreement.
The operator owns the allowlist; everything off it stays manual.

## Configuration

```jsonc
{
  "learningApply": {
    "autoApply": {
      "enabled": false,            // OFF by default
      "keys": [],                  // e.g. ["consensus.maxIterations"]
      "revertOnRegression": true,
      "regressionDelta": 0.05
    }
  }
}
```

Fully defaulted + partial-merge friendly (`AutoApplyConfigSchema`, nested
in `LearningApplyConfigSchema`). See `docs/AUTO-APPLY.md`.

## Upgrade

```
/plugin uninstall vibeflow@vibeflow
/plugin install vibeflow@vibeflow
/reload-plugins
```

No migration. `autoApply` is off by default — nothing changes until you
opt a key into the allowlist.
