# VibeFlow v2.25.0 — ARCHITECTURE gets an author, and phase-runner runs skills (not agents)

Two ARCHITECTURE-phase gaps surfaced by live AntOS + FlowBridge walks, fixed
together.

## Added: `/vibeflow:architecture-bootstrap`

ARCHITECTURE had the same gap DESIGN had before `design-bootstrap`:
`architecture-validator` **validates** `docs/architecture.md` (its hard
precondition is that the doc exists and is non-empty) — but **nothing authored
it**. On a greenfield project the phase stalled, and operators ended up writing
the architecture + ADRs by hand.

The new author-side guide (counterpart to `design-bootstrap`) **asks the
technology / deployment baseline** — the one consequential, expensive-to-change
fork — never inventing it silently:

| # | Baseline | Documents |
|---|---|---|
| 1 | **Propose sensible defaults** | a domain-appropriate cloud-native baseline (region, gateway + services, datastore, audit/event log, authn, cross-platform), each a **revisitable ADR** |
| 2 | **You specify the stack** | exactly the language/framework, cloud, datastore, mobile approach you give |
| 3 | **Stack-agnostic** | logical architecture + integration contracts + security/NFRs + structural ADRs only; defer vendor/language |

Then it authors **`docs/architecture.md`** (logical/component architecture with
boundaries, data model, integration contracts incl. external/licensed partners,
a **domain-policy-aware** security & privacy architecture, NFRs, deployment
baseline, requirements trace) + one revisitable **`docs/adr/ADR-NNN-<slug>.md`**
per decision, and arms the consensus marker → `▶ Next: /vibeflow:phase-runner`.

For `financial`, it covers the policy areas `architecture-validator` checks —
at-rest encryption (per-tenant envelope / KMS), PII redaction, WORM audit +
anchoring, RLS (no bypass), NTP time integrity, fail-closed secrets, a
kill-switch — head-on, so the validator finds an architecture that *addresses*
the policies instead of one that's silent. Fewer round-trips to APPROVED.

Docs: `docs/ARCHITECTURE-PHASE.md`.

## Fixed: phase-runner runs analyzers as skills, not agents

phase-runner's Step 2 told the model to "invoke the skill via its slash command
(Claude **forks** it)". On FlowBridge, "fork" led a session to spawn a
general-purpose / Explore subagent (via the Agent tool) instead of running
`architecture-validator` as a skill — and the agent returned codebase
*exploration*, not the validation, its marker, or its auto-satisfy. So the
automated policy gate was silently bypassed and the architecture had to be
validated by hand.

Step 2 now says it explicitly: **run each analyzer as a skill — use the Skill
tool (or `/vibeflow:<analyzer>`), do NOT spawn a general-purpose or Explore
agent.** This keeps the PLANNING/TESTING analyzers
(`test-strategy-planner`, `traceability-engine`, `coverage-analyzer`, …)
running with their gates, not redone by hand.
