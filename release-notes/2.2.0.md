# VibeFlow v2.2.0 — Unified consensus, mode retired, skill output contract fixed

Three field-reported bugs from v2.1.0 testing close with this release.
All three were telling the same story: consensus was still gated on a
mode switch that no longer made sense, and analysis skills were
emitting their reports to chat instead of writing them to
`.vibeflow/reports/`.

## Bug 1 — "solo mode'da codex/gemini girmez" was wrong

`skills/consensus-orchestrator/SKILL.md` was still gating external AI
reviews behind a "Team Mode Only" section. But `codex` and `gemini`
CLIs use the **operator's own authenticated session** (ChatGPT Plus,
Gemini Pro, Workspace, etc.) — there's no VibeFlow-emitted API key
and no per-call billing. The mode gate had no justification.

**Fixed.** Consensus now runs every CLI that is on `PATH`, full stop.
`hooks/scripts/consensus-aggregator.sh` detects reviewers via
`command -v` at call time:

```
default quorum = claude-reviewer (always)
               + codex  (if CLI on PATH)
               + gemini (if CLI on PATH)
```

Operators who need to pin a specific count (offline CLI, CI with a
single reviewer, etc.) set `consensus.quorum` in
`vibeflow.config.json`:

```json
{ "consensus": { "quorum": 3 } }
```

`hooks/scripts/trigger-ai-review.sh` no longer short-circuits
"in solo mode" — the review marker is written whenever the diff
crosses 50 lines; which reviewers respond is downstream's problem.

## Bug 2 — `reviewer=unknown` / `verdict=UNKNOWN` polluting consensus

Running `/vibeflow:prd-quality-analyzer` was producing verdict files
like:

```json
{"total":1, "unknown":1, "verdict":"REJECTED"}
```

Root cause: `hooks/scripts/consensus-aggregator.sh` was a `*` matcher
on `SubagentStop` and recorded every subagent stop, regardless of
whether it was a reviewer. When `Explore`, `test-analyst`, or
`codebase-explorer` finished, the aggregator couldn't extract a
verdict from their output and logged `reviewer=unknown,
verdict=UNKNOWN` — which then pulled the aggregate toward REJECTED.

**Fixed.** The aggregator now filters by subagent name (allow-list:
`claude-reviewer`, `reviewer`, `*-reviewer`, `consensus-*`). Anything
else is silently ignored. When a reviewer-class subagent does run but
its output has no recognisable verdict, the entry is skipped rather
than logged — no more synthetic UNKNOWNs.

Also: malformed `SubagentStop` payloads (JSON with embedded `\n`
escapes that got interpreted as real newlines mid-pipe) no longer
abort the hook with `exit 5`. Fail-safe path: parse-failure →
`{"continue":true}` + exit 0.

## Bug 3 — Analysis skills printing to chat only

`prd-quality-analyzer` produced two detailed reports during a real
session but never wrote them to disk. Their `allowed-tools` was
`Read Grep Glob` — no `Write` permission. The same bug affected
three other analysis skills.

**Fixed.** Every skill that declares a `## Output Files` section now
carries `Write` in `allowed-tools` and names its
`.vibeflow/reports/<name>.md` target path explicitly, with a **"never
print to chat only"** directive at the top of the section:

| Skill | Outputs |
|---|---|
| `prd-quality-analyzer` | `prd-quality-report.md`, `prd-cost-avoidance.md` |
| `test-strategy-planner` | `scenario-set.md`, `test-strategy.md` |
| `architecture-validator` | `architecture-report.md`, `adr-NNN-*.md` |
| `traceability-engine` | `rtm.md`, `traceability-gaps.md` |

Regression sentinel in `tests/integration/sprint-4.sh`: any skill with
an `## Output Files` section must carry `Write` (or `MultiEdit`). If
anyone copies a skill template and forgets the permission, the CI
catches it.

## Also — `mode` concept fully retired

Sprint 11-E removed `mode` from the manifest and the state backend,
but the hook layer kept reading it for status lines, and `init`
still prompted users to pick solo or team. This release finishes
the job:

- `vf_mode()` helper deleted from `hooks/scripts/_lib.sh`
- Every hook (`load-sdlc-context`, `compact-recovery`,
  `trigger-ai-review`, `consensus-aggregator`) is free of `MODE=`
  reads
- Status line no longer prints `mode=...`
- `docs/CONFIGURATION.md` sample config + fields table + `userConfig`
  table all cleaned up (sample gained a `consensus.quorum` example)
- `docs/HOOKS.md` rewrote the trigger-ai-review + consensus-aggregator
  subsections around CLI detection
- Committed `vibeflow.config.json` files (root + `examples/*`) have
  no `mode` field
- Test fixtures in `hooks/tests/run.sh` use
  `jq '. + {consensus:{quorum:N}}'` overrides instead of
  `make_project <phase> <mode>`

Upgrading from v2.0/v2.1: if your existing `vibeflow.config.json`
still carries `"mode": "solo"`, it's harmlessly ignored. Remove it
next time you edit the file or let `/vibeflow:init` regenerate the
template.
