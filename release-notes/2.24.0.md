# VibeFlow v2.24.0 — a fair design comparison (rendered vs rendered)

Running v2.23.0's compare-both on a real project surfaced a fairness bug in
the *comparison itself*: Claude produced markdown/ASCII wireframes, Figma
produced polished `.png` exports — so Figma "looked nicer" every time, **not
because the design was better, but because it was rendered and Claude's wasn't.**
You can't judge a design you can't see.

## Fixed: compare rendered-vs-rendered

In option 4 (Both/compare), the Claude-native candidate now also emits
**self-contained HTML/CSS mockups** of the hero screens
(`design/candidates/claude-native/mockups/<screen>.html`):

- inline CSS driven by `design-tokens.json` (the real palette / type / spacing),
- real content (not lorem) + the key states,
- responsive + accessible (semantic HTML, focus styles, ARIA).

Open them in a browser to see the actual UI — at Figma-comparable fidelity. If
a screenshot tool is available in the session, they're captured to `.png` so
`design/design-comparison.md` shows **image-vs-image**. Either way, you're now
weighing two *rendered* designs, not a sketch against a picture.

The Claude-native path (option 1) also prefers a rendered HTML mockup per hero
screen over an ASCII sketch alone — so even without comparing, you can *see*
the design.

## Also: what "merge" means

At the pick step, "merge" confused operators. It's now spelled out: the two
candidates are the **same** design in different media (same tokens, screens,
gating) — there's nothing conflicting to reconcile. **Merge = keep both, each
in its strongest role:** the Claude spec stays canonical (most complete,
in-repo, diff-able) and the Figma file / HTML mockups stay as the living visual
+ Dev-Mode hand-off. Pick 1/2 only when you want a single medium.
