# VibeFlow v2.39.0 — phase-write-guard is monorepo-aware

A live ANTOS (monorepo) TESTING run hit a hook block that shouldn't have been a
block: adding a Stryker `// Stryker disable next-line` annotation — for a
*proven equivalent mutant* — to `packages/shared/src/dashboard.ts` was hard-blocked
by `phase-write-guard`.

## Why

`phase-write-guard`'s source `warn` glob was `src/**`, which matches only a
**top-level** `src/…`. In a monorepo, source lives under `packages/*/src/…` or
`apps/*/src/…` — which matched neither the phase's `allow` list nor that `warn`
pattern, so it fell through to a **hard block** (the default).

But the *intent* for TESTING (and DEPLOYMENT) is a **warn**, not a block: source
writes are discouraged but allowed-with-a-heads-up, because legitimate
late-phase touches happen — exactly like a Stryker equivalent-mutant annotation,
which is documentation that lives in the source and is reviewable. The
monorepo gap turned that soft warn into a wall.

## Fix

The `warn` lists for TESTING + DEPLOYMENT now include **`**/src/**`** alongside
`src/**`. So:

- monorepo source (`packages/*/src/…`, `apps/*/src/…`) → **warn (soft-allow)**,
  same as a top-level `src/…`;
- a non-`src` monorepo path (`packages/*/lib/…`) → still **block** (the warn is
  scoped to `/src/` segments, not over-permissive);
- REQUIREMENTS still **hard-blocks** all source (no regression).

Test patterns (`**/*.test.*`) were already monorepo-aware — this brings source
into line with them. Pinned by `tests/integration/sprint-51.sh` (static + a
runtime matcher probe). Docs: `docs/PHASE-BOUNDARIES.md`.
