# VibeFlow v2.3.0 — MyVibe closed-loop, end-to-end

v2.3.0 completes the MyVibe promise: an artifact produced by any
analysis skill gets reviewed by Claude + codex + gemini, the
arbiter decides which suggestions to apply in the current phase,
and the operator applies the resulting diff with one command.

## Four layers, each independently safe

```
[analysis skill] ─► [orchestrator → 3 reviewers] ─► [aggregator]
                                                         │
                                                         ▼
                                          status ∈ {APPROVED,
                                                    NEEDS_REVISION}
                                                         │
                                                  NEEDS_REVISION
                                                         │
                                                         ▼
                                              [arbiter] ─► .patch files
                                                         │
                                                         ▼
                                      operator ─► [apply-arbiter-patch]
                                                         │
                                                         ▼
                                              target files on disk

                              L3 phase-gate
      /vibeflow:advance <phase> ──► refuses unless fresh per-phase
                                    APPROVED consensus exists
```

## What's fixed

**codex/gemini verdicts never reached the aggregator.** The
orchestrator ran them as raw bash subprocesses, which don't emit
`SubagentStop` events. Aggregator expected three reviewers, got
one, waited 600s, demoted the APPROVED outcome to NEEDS_REVISION.
This is why you saw `reviewer:"unknown"` with quorum=1 on a host
with both CLIs installed.

Fix (S15-A): orchestrator now appends one JSONL line per CLI
directly to `.vibeflow/state/consensus/<session>.jsonl` in the
aggregator's exact schema. Per-CLI 90s timeout. When the
claude-reviewer subagent finishes and its SubagentStop handler
runs, the aggregator sees all three reviewers already logged and
finalises the session on the first tick.

## What's new

### Skill auto-invoke (L2)

Six analysis skills — `prd-quality-analyzer`,
`architecture-validator`, `test-strategy-planner`,
`traceability-engine`, `coverage-analyzer`,
`release-decision-engine` — now end with a mandatory
"Final Step: Auto-Consensus" section. After writing their
reports, they invoke `/vibeflow:consensus-orchestrator` on the
primary report. Skip condition is a single env var:
`VF_SKIP_AUTO_CONSENSUS=1`.

### Phase gate (L3)

Every phase except DEVELOPMENT carries
`consensus.<phase>.approved` in its exit criteria:

| Phase | Scoped criterion |
|---|---|
| REQUIREMENTS | `consensus.requirements.approved` |
| DESIGN | `consensus.design.approved` |
| ARCHITECTURE | `consensus.architecture.approved` |
| PLANNING | `consensus.planning.approved` |
| DEVELOPMENT | _(omitted — commit-time marker covers it)_ |
| TESTING | `consensus.testing.approved` |
| DEPLOYMENT | `consensus.deployment.approved` |

The validator scope-checks `lastConsensusPhase` — a fresh
REQUIREMENTS verdict no longer carries through to DESIGN advance.
`force: true` bypasses. Legacy `consensus.approved` on
ARCHITECTURE is aliased through v2.3.x; drop in v2.4.0.

### Arbiter (L4)

`consensus-arbiter` is a new skill. It reads the session jsonl +
verdict + currentPhase + domain, walks a 10-rule decision matrix,
and emits:

- `.vibeflow/reports/arbiter-decisions.md` — audit trail (every
  suggestion with APPLY / DEFER / REJECT + rationale).
- `.vibeflow/state/patches/<session>/NN-<slug>.patch` — one
  `git apply`-compatible unified diff per APPLY.
- `manifest.json` — machine-readable APPLY set + iteration
  counter.

**Arbiter never writes to source files.** Diff-first contract —
the operator sees the change before it lands.

Rules (first match wins, full table in `docs/ARBITER.md`):

- out-of-phase → DEFER
- `type == "question"` → DEFER (answer belongs in the artifact)
- domain policy conflict (financial invariant weakening, etc.) → REJECT
- vague `proposed_change` → DEFER
- ≥2 reviewers agree at ≥ medium priority → APPLY consolidated
- single reviewer, low priority → DEFER
- single reviewer, ≥ medium, type=fix → APPLY
- single reviewer, enhancement, low risk tolerance → DEFER
- cross-reviewer conflict on same target → DEFER + "manual
  resolution needed"
- otherwise → DEFER

Iteration guard: manifest tracks how many times the same session
has been re-arbitrated. At iteration 3 the skill stops producing
patches and marks the session `deferred_for_human_review`.

### Apply (operator-in-the-loop)

`apply-arbiter-patch` is the second new skill. It:

1. Resolves the session (arg or most recent).
2. Computes `+N/-N` counts per patch via `git apply --numstat`.
3. Emits a single diff summary block.
4. Asks for `y/N` — unless `--yes`.
5. Runs `git apply --check` then `git apply` per patch. A
   conflict aborts the remainder with a "regenerate" hint.
6. Flips `Applied: false` → `Applied: true` in
   `arbiter-decisions.md`.
7. `--run-tests` runs the project's test command; failure prints
   the `git checkout HEAD -- <files>` rollback line. No
   auto-revert.

### Marker drain (post-commit half)

`load-sdlc-context.sh` reads `review-pending.json` on SessionStart
and emits:

```
VibeFlow: unreviewed commit pending (sha=…, +N lines).
ACTION REQUIRED: run /vibeflow:consensus-orchestrator to drain the review queue.
```

Marker ages out after 24h so stale shas don't send Claude on a
wild goose chase.

### Config: `consensus.quorum`

Already shipped in 2.2.0, now documented end-to-end. Pin the
expected reviewer count when a CLI is offline:

```json
{ "consensus": { "quorum": 1 } }
```

## Upgrade

```bash
claude plugin marketplace update vibeflow
claude plugin install vibeflow@vibeflow
```

After upgrade, running `/vibeflow:prd-quality-analyzer docs/prd.md`
(or any of the six analysis skills) auto-chains into
consensus-orchestrator, which auto-chains into consensus-arbiter
on NEEDS_REVISION verdicts. You then run
`/vibeflow:apply-arbiter-patch` to land the approved changes.

Set `VF_SKIP_AUTO_CONSENSUS=1` for exploratory work where you
don't want the chain to fire; the phase-gate still enforces on
advance.
