# VibeFlow v2.5.2 — `/vibeflow:advance` default-to-next

Skill polish. Calling `/vibeflow:advance` with no argument now
advances to the next phase in the canonical SDLC order
automatically. v2.5.1 required the target phase explicitly; that
was needlessly verbose when 99% of advances just move one step
forward.

## What's new

### Optional `TARGET_PHASE`

```
/vibeflow:advance                 # next phase from currentPhase
/vibeflow:advance DESIGN          # explicit target (unchanged)
/vibeflow:advance humanOverrideNote="..."  # next + override note
```

Phase order:
```
REQUIREMENTS → DESIGN → ARCHITECTURE → PLANNING
             → DEVELOPMENT → TESTING → DEPLOYMENT
```

The skill reads `vibeflow.config.json.currentPhase` (falling back
to `sdlc_get_state` if the config doesn't carry a live phase) and
picks the canonical next phase. At DEPLOYMENT it stops with
"Already at the last phase; nothing to advance" instead of
failing noisily.
