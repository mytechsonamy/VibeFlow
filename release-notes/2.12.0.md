# VibeFlow v2.12.0 — Self-Correcting Auto-Apply

**Sprint 24.** Sprint 23 made config auto-apply autonomous (apply +
auto-revert). v2.12.0 makes it **self-correcting**: the loop learns from
its own auto-tuning outcomes and stops auto-applying keys that never
stick — plus multi-key transactional revert.

## The meta-loop

Every auto-tune now leaves a queryable trail in `history.jsonl`:
`auto-apply` (learning-apply applied it) → `auto-revert` (next round
regressed, aggregator rolled it back) or `auto-apply-held` (next round
held, the tune stuck). Three pieces close the loop on top of that:

- **Detector (S24-B).** `learning-loop-engine`'s `consensus-history` mode
  gains `auto-tune-ineffective`: a key whose `auto-apply` rows are
  followed by `auto-revert` (not `held`) in ≥ 3 attempts at a revert rate
  ≥ 0.5 is flagged — "remove `<key>` from `autoApply.keys`; tuning it
  doesn't move agreement." (`patternCatalogVersion` → 3.)
- **Self-demote (S24-C).** Before auto-applying an allowlisted key,
  `learning-apply` counts its `auto-revert` rows; ≥ `demoteAfterReverts`
  (default 3) ⇒ the key is **demoted to propose-only for the run** even
  while it stays allowlisted (`Applied: demoted`). Cooldown is
  per-sprint; self-demote is the lifetime guard.

## Multi-key transactional revert (S24-D)

With `autoApply.transactional` (default true), a run that auto-applies
several keys takes **one** pre-batch snapshot and arms **one** watch over
the whole set (`watch.json.keys[]`). If the next round regresses, the
aggregator restores that snapshot — reverting the **set atomically** —
and cools down every key in it. The set holds or reverts as a unit, so a
good tune isn't kept beside a bad one against a baseline that was never
measured for that mix. `transactional: false` restores the Sprint-23
one-key-at-a-time behaviour. The aggregator reads `keys // [key]`, so
Sprint-23 single-key watches still work unchanged.

## Configuration

```jsonc
{
  "learningApply": {
    "autoApply": {
      "enabled": false,             // still OFF by default
      "keys": [],
      "revertOnRegression": true,
      "regressionDelta": 0.05,
      "demoteAfterReverts": 3,      // Sprint 24: lifetime self-demote
      "transactional": true         // Sprint 24: atomic multi-key revert
    }
  }
}
```

All additive + defaulted; with `autoApply` off (the default) nothing
engages. See `docs/META-LEARNING.md`.
