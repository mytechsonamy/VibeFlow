# VibeFlow v2.26.0 — skills can actually execute (removed `agent: Explore`)

This is the real root cause behind a bug we'd been chasing for several
releases: **"the analyzer/validator returned a codebase exploration, not its
report."** It hit `architecture-validator` and `release-decision-engine`, and
v2.25.0 misdiagnosed it as the *model* spawning a general agent. It wasn't the
model — it was the skills' own frontmatter.

## Root cause

**27 skills carried `agent: Explore` in their frontmatter.** That directive
runs the skill on Claude Code's **Explore agent** — a read-only search agent
whose toolset **excludes `Write`** (and `Edit`). So a skill declaring
`allowed-tools: Read Write Grep Glob` and whose whole job is to *write a
report* (`architecture-report.md`, ADRs, `prd-quality-report.md`, …) literally
**could not write anything** when invoked. It fell back to summarizing the
codebase — which looked like "exploration" — and its auto-satisfy criterion +
policy gate never ran, so `phase-runner`'s automated gate was silently bypassed
and the operator had to redo the work by hand.

A live AntOS ARCHITECTURE run nailed it: `architecture-validator` was invoked
**via the Skill tool** (not a spawned agent) and *still* came back as
exploration — because the routing was baked into the skill, not the call site.

## Fix

**Removed `agent: Explore` from all 27 skills.** `context: fork` is kept — a
forked skill writes fine without the read-only Explore routing
(`apply-arbiter-patch` has always had `context: fork` with no `agent:` and
writes/patches without trouble). The analyzers and validators now run with
their real toolset and produce their reports + satisfy their criteria.

Skills fixed include: `architecture-validator`, `prd-quality-analyzer`,
`test-strategy-planner`, `traceability-engine`, `coverage-analyzer`,
`release-decision-engine`, `mutation-test-runner`, `business-rule-validator`,
`invariant-formalizer`, `decision-recommender`, `learning-loop-engine`,
`visual-ai-analyzer`, the test-writers, and more.

## Why it sometimes "worked anyway"

The symptom was intermittent — `prd-quality-analyzer` produced reports in some
runs — because the model can emit a report as plain text and a later step
writes it, masking the missing `Write`. But it was never reliable, and for the
validators (whose value is the automated policy gate + criterion auto-satisfy)
the failure was real every time it routed to Explore. The gate is no longer
chance-dependent.

Pinned by `tests/integration/sprint-38.sh` — a regression guard that asserts no
skill frontmatter carries `agent: Explore`, and that the Write-needing
validators keep `Write` without the Explore routing.

## After updating

Re-run `phase-runner` for any phase whose analyzer was returning exploration
(ARCHITECTURE / PLANNING / TESTING / DEPLOYMENT). The analyzer should now run,
write its report, and auto-satisfy its criterion — no manual redo.
