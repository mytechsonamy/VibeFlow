# VibeFlow v2.38.0 — the consensus-gate escape hatch works with two env vars

A small but real papercut, surfaced on a live ANTOS ARCHITECTURE run: the
documented bypass `VF_SKIP_CONSENSUS_GATE=1 <command>` worked, but
`VF_SKIP_CONSENSUS_GATE=1 VF_ALLOW_PHASE_WRITE=1 <command>` (two prefix env vars —
exactly what a phase-write *and* gate-skip needs together) was still blocked, so
the session burned several attempts before falling back to the single-var form.

## Why

`consensus-gate.sh` only checked the bypass as an **exported env var**. Claude
Code reliably exports a *single* leading `VAR=val` assignment into the hook
environment, but not two — so with a two-var prefix the gate never saw the skip
flag and blocked the call.

## Fix

The gate now also parses the **leading env-var prefix** of the command string —
the run of `VAR=val` tokens before the first real command word — and honors
`VF_SKIP_CONSENSUS_GATE=1` (or `=true`) found there. So the override is:

- **order-independent** — `VF_SKIP_CONSENSUS_GATE=1 VF_ALLOW_PHASE_WRITE=1 …` and
  the reverse both work;
- **count-independent** — any number of sibling prefix vars is fine;
- **safe** — a mention of the var inside a quoted string arg does **not** bypass
  (awk stops at the first non-assignment token), and a normal command with an
  armed marker still blocks.

The env-var check (the single-var path) stays, so nothing that worked before
changes. Pinned by `tests/integration/sprint-50.sh` (static + runtime probes).
