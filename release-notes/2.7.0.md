# VibeFlow v2.7.0 — Primary-Artifact Refocus + End-to-End Phase Automation

**Sprint 19.** Three architectural fixes ship together. Consensus
now reviews the **project document** (PRD, ADR, test-strategy)
instead of the analyzer's **opinion** of that document.
Aggregator stops promoting zero-reject verdicts to REJECTED (the
bug that killed FlowBridge_TR's iteration loop at round 1). And
the full analyzer → consensus → specialist → apply → advance walk
collapses to one command: `/vibeflow:phase-runner`.

## The core fix: review the PRD, not the report

Before v2.7.0, every analysis skill's Final Step wrote a marker
whose `artifact` field pointed at the analyzer's own report
(e.g. `prd-quality-report.md`). The orchestrator piped that
report into reviewer prompts, so codex + gemini + claude ended
up reviewing the analyzer's taxonomy ("move AMB-T-002 to HIGH",
"CONF-D-001 is a false positive") rather than the PRD's
readiness.

**Marker schema v2** fixes this:

```json
{
  "primaryArtifact": "docs/FlowBridge_TR_SRS_v1_1.docx",
  "evidence": [
    ".vibeflow/reports/prd-quality-report.md",
    ".vibeflow/reports/prd-cost-avoidance.md"
  ],
  "artifact": ".vibeflow/reports/prd-quality-report.md",
  "requiredCommand": "/vibeflow:consensus-orchestrator docs/FlowBridge_TR_SRS_v1_1.docx",
  "createdAt": "…",
  "createdBy": "prd-quality-analyzer"
}
```

`primaryArtifact` is what reviewers actually review. `evidence[]`
is analyzer context, distilled to ≤500 tokens per source in the
reviewer prompt. Legacy `artifact` + `requiredCommand` stay so
`consensus-gate.sh` and pre-v2.7.0 invocations keep working
unchanged.

Eight analyzer skills updated (prd-quality-analyzer,
architecture-validator, test-strategy-planner,
traceability-engine, coverage-analyzer, mutation-test-runner,
release-decision-engine, deploy-verifier). See
`docs/PRIMARY-ARTIFACT.md` for the full per-phase primary map.

## The status-rule fix: reviewer sentiment is authoritative

FlowBridge_TR hit a REJECTED verdict from 2 NEEDS_REVISION +
1 APPROVED reviewers — zero actually voted reject. The pre-19
aggregator rule promoted on `criticalTotal >= 2` unconditionally.

New rule:

```
if (rejected * 2) > total        → REJECTED  (strict majority)
elif rejected >= 1 AND            → REJECTED  (escalation needs a
     criticalTotal >= 2                        real reject vote)
elif agreement >= 0.9 AND
     criticalTotal == 0           → APPROVED
else                              → NEEDS_REVISION
```

Zero-reject with high critical count lands as NEEDS_REVISION
so iteration can continue through the arbiter / specialist
path. The specialist's `consensus-specialist` skill also gains
a matching 4-case guardrail — genuine REJECTED (rejected≥1)
stops with operator triage; everything else dispatches.

## Apply auto-chain: convergence without manual shepherding

`apply-arbiter-patch` gains **Step 9**: after a successful
`git apply` (plus passing tests when `--run-tests` is set), the
skill writes a new `consensus-needed.json` marker pointing at
the **same primaryArtifact** for iteration N+1. The next tool
call is blocked by `consensus-gate`, forcing the orchestrator
to re-evaluate the updated artifact.

Iteration tracking piggybacks on `verdict.json.round` (Sprint
17-A field) — no new `manifest.iteration` state. Bounded by
`consensus.maxIterations` (default 5) and a convergence-stall
guard (agreement delta ≤0.05 over 2 rounds → stop with
advisory). Opt-outs: `--no-chain` flag, `VF_SKIP_AUTO_CHAIN=1`.

## `phase-runner` — one command per phase

New skill `/vibeflow:phase-runner [TARGET_PHASE]`. Composes:

```
analyzer(s) → consensus-orchestrator → specialist/arbiter →
apply-arbiter-patch (auto-chain) → mcp__sdlc-engine__sdlc_advance_phase
```

Phase → analyzer map is hardcoded. REQUIREMENTS →
prd-quality-analyzer; ARCHITECTURE → architecture-validator;
PLANNING → test-strategy-planner + traceability-engine;
DEVELOPMENT → quality-gates; TESTING → coverage-analyzer +
mutation-test-runner; DEPLOYMENT → release-decision-engine +
deploy-verifier. DESIGN has no analyzer shipped — phase-runner
announces the manual-criterion reminder from
`docs/AUTO-SATISFY.md` and invokes consensus directly.

Config surface: `phaseRunner.autoAdvance` (default true),
`phaseRunner.maxConvergenceAttempts` (default 3). The runner
calls `mcp__sdlc-engine__sdlc_advance_phase` directly — no
shelling out through `/vibeflow:advance`.

Flags:
- `--pause-between-steps` — step through with operator confirms
- `--no-auto-advance` — stop at APPROVED, don't advance
- `--no-auto-chain` — forward `--no-chain` to apply-arbiter-patch

## FlowBridge_TR walkthrough (post-upgrade)

```
/vibeflow:phase-runner
  ├─ prd-quality-analyzer → writes v2 marker (primary=PRD, evidence=[reports])
  ├─ consensus-orchestrator docs/PRD.docx
  │     Round 1: 2 NEEDS_REVISION + 1 APPROVED, criticalTotal=2, rejected=0
  │     → status = NEEDS_REVISION (S19-C: no reject votes)
  ├─ consensus-specialist → prd-rewriter produces PRD diff
  ├─ apply-arbiter-patch --run-tests
  │     patches apply, tests pass → Step 9 writes round=2 marker
  ├─ consensus-orchestrator docs/PRD.docx (round 2)
  │     Round 2: 3 APPROVED on updated PRD
  │     → status = APPROVED
  └─ mcp__sdlc-engine__sdlc_advance_phase REQUIREMENTS → DESIGN
```

Single command; end-to-end convergence.

## Upgrade

```
/plugin uninstall vibeflow@vibeflow
/plugin install vibeflow@vibeflow
/reload-plugins
```

No config migration needed. The marker v2 fields are additive;
in-flight sessions with legacy markers still resolve via
fallback to `artifact`.
