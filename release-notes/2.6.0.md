# VibeFlow v2.6.0 — Full Auto-Satisfy Rollout

**Sprint 18.** Every automatable SDLC exit criterion is now
satisfied by the skill that produces its authoritative evidence.
Phase transitions become single-command advance sequences. The
three criteria that require genuine human judgment
(`design.approved`, `accessibility.verified`, `sprint.planned`)
stay operator-driven by design, and `docs/AUTO-SATISFY.md`
documents them with rationale.

## What's new

### `quality-gates` skill

```
/vibeflow:quality-gates
```

Runs lint + typecheck + unit tests:

- **Explicit config**: reads `vibeflow.config.json.tech.lintCommand`,
  `tech.typecheckCommand`, `tech.testCommand` if present.
- **Inferred defaults** from `tech.language`: JS/TS →
  `eslint`/`tsc`/`npm test`, Python → `ruff`/`mypy`/`pytest`,
  .NET → `dotnet format`/`dotnet test`, Go → `go vet`/`go test`,
  Rust → `cargo clippy`/`cargo test`.

Writes `.vibeflow/reports/quality-gates-<timestamp>.md` with
per-command exit codes + truncated output. Satisfies
`quality.gates.passed` only when every command that actually
ran exited 0. Missing tools are SKIPPED (not failed) but the
criterion only auto-satisfies if at least one command ran
successfully and none failed.

### `deploy-verifier` skill

```
/vibeflow:deploy-verifier
```

Post-deployment smoke runner that reads
`vibeflow.config.json.deployment`:

```json
{
  "deployment": {
    "environment": "staging | production",
    "endpoints": [
      { "url": "https://api.example.com/health", "expect": { "status": 200, "bodyIncludes": "ok" } }
    ],
    "ci": { "provider": "github", "repo": "owner/repo", "ref": "v2.6.0" },
    "observability": { "enabled": true, "errorBudgetBurnThreshold": 0.1 }
  }
}
```

Calls:
1. `mcp__dev-ops__do_pipeline_status` — CI green on the configured ref
2. `curl` each configured endpoint — status code + body substring match
3. `mcp__observability__ob_health_dashboard` — no active burn above threshold

Satisfies `deployment.verified` + `health.checks.passed` on
overall PASS. Writes the consensus-needed marker for the third
DEPLOYMENT criterion so multi-AI review still runs.

On failure, prints a loud advisory with the specific failing
check + rollback command pulled from `docs/runbooks/` (if
present). No auto-rollback.

### Analyzer auto-satisfy extensions

Existing analyzers that produce authoritative signals now call
`mcp__sdlc-engine__sdlc_satisfy_criterion` directly:

- **architecture-validator** → `adr.recorded`, conditional on
  verdict ≠ BLOCKED
- **test-strategy-planner** → `test-strategy.approved`, unconditional
  (skill is generative)
- **coverage-analyzer** → `coverage.met`, conditional on verdict == PASS
- **mutation-test-runner** → `mutation.score.acceptable`,
  conditional on verdict == PASS (mutation-test-runner also
  gains its first Final Step with auto-consensus marker)

Every conditional auto-satisfy gates on the skill's own
report-level verdict token. BLOCKED / FAIL / NEEDS_REVISION
verdicts keep the criterion unsatisfied, so the phase gate
correctly stays closed.

### Orchestrator DEVELOPMENT path

On DEVELOPMENT + APPROVED/HUMAN_APPROVAL_REQUIRED,
consensus-orchestrator now **also** satisfies `code.reviewed`.
DEVELOPMENT is the one phase without a scoped
`consensus.<phase>.approved` criterion (Sprint 15-C
excluded it); the orchestrator's DEVELOPMENT verdict IS the
code-reviewed signal.

## Walkthrough — fully automated phase transitions

```
/vibeflow:prd-quality-analyzer docs/PRD.md
  → prd.approved ✓ + testability.score>=60 ✓
/vibeflow:consensus-orchestrator .vibeflow/reports/prd-quality-report.md
  → consensus.requirements.approved ✓
/vibeflow:advance                                # → DESIGN

# DESIGN phase:
# design.approved + accessibility.verified require operator sign-off
mcp__sdlc-engine__sdlc_satisfy_criterion {projectId, criterion: "design.approved"}
mcp__sdlc-engine__sdlc_satisfy_criterion {projectId, criterion: "accessibility.verified"}
/vibeflow:consensus-orchestrator <design-spec>
/vibeflow:advance                                # → ARCHITECTURE

/vibeflow:architecture-validator
  → adr.recorded ✓ (verdict ≠ BLOCKED)
/vibeflow:consensus-orchestrator <arch-report>
/vibeflow:advance                                # → PLANNING

/vibeflow:test-strategy-planner
  → test-strategy.approved ✓
# sprint.planned requires operator
mcp__sdlc-engine__sdlc_satisfy_criterion {projectId, criterion: "sprint.planned"}
/vibeflow:consensus-orchestrator <test-strategy>
/vibeflow:advance                                # → DEVELOPMENT

# commit code, then:
/vibeflow:quality-gates
  → quality.gates.passed ✓ (lint + typecheck + tests all green)
/vibeflow:consensus-orchestrator <commit-review>
  → code.reviewed ✓ (on APPROVED DEVELOPMENT verdict)
/vibeflow:advance                                # → TESTING

/vibeflow:coverage-analyzer
  → coverage.met ✓ (verdict == PASS)
/vibeflow:mutation-test-runner
  → mutation.score.acceptable ✓ (verdict == PASS)
/vibeflow:consensus-orchestrator <coverage-report>
/vibeflow:advance                                # → DEPLOYMENT

# after deploy:
/vibeflow:deploy-verifier
  → deployment.verified ✓ + health.checks.passed ✓
/vibeflow:consensus-orchestrator .vibeflow/reports/deploy-verification.md
/vibeflow:advance                                # → done
```

Every transition is one command (plus the three documented
manual sign-offs in DESIGN and PLANNING).

## Graceful fallback (unchanged from v2.5.4)

Every auto-satisfy site has an MCP-unreachable fallback that
prints the manual command the operator should run. The
artifact on disk stays the source of truth; only the state
write is skipped.

## Upgrade

```
/plugin uninstall vibeflow@vibeflow
/plugin install vibeflow@vibeflow
/reload-plugins
```

No config migration needed. New config surfaces
(`tech.lintCommand`, `tech.typecheckCommand`,
`tech.testCommand`, `deployment.*`) are all optional with
sensible defaults.
