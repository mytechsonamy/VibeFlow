# VibeFlow v2.4.0 — Deterministic Auto-Consensus Chain

**Sprint 16.** Closes the remaining gap in the MyVibe closed loop:
analysis skills now *enforce* consensus via a filesystem marker +
PreToolUse hook, not just trust the skill to invoke a slash
command. Forked subagents, compaction, or a distracted main agent
can no longer silently skip review.

## What changed

Every L1 analysis skill (`prd-quality-analyzer`,
`architecture-validator`, `test-strategy-planner`,
`traceability-engine`, `coverage-analyzer`,
`release-decision-engine`) now writes
`.vibeflow/state/consensus-needed.json` as its final step. A new
`PreToolUse` hook — `consensus-gate.sh` — refuses every
`Bash | Write | Edit` tool call while that marker is present,
surfacing the required `/vibeflow:consensus-orchestrator` command
to the model until it is run. The orchestrator, the arbiter, and
`apply-arbiter-patch` all drain the marker on success, so the
chain is self-clearing.

```
prd-quality-analyzer writes report
         │
         ▼
writes consensus-needed.json marker  ◄── NEW (Sprint 16-C)
         │
         ▼
operator's next tool call
         │
         ▼
consensus-gate.sh blocks it        ◄── NEW (Sprint 16-A)
   stderr: "RUN THIS NEXT:
            /vibeflow:consensus-orchestrator <report>"
         │
         ▼
consensus-orchestrator runs
         │
         ▼
drains both markers on APPROVED/NEEDS_REVISION/REJECTED  ◄── Sprint 16-B
```

## Why a marker, not a slash-command invoke

Claude Code has no programmatic `SlashCommand` tool. A skill
cannot instruct Claude to run `/vibeflow:x` in a way that actually
fires — it can only print text. That prose is a hint, defeated by
forking, compaction, or a main agent that moves on to the next
request. A file on disk survives all three; a `PreToolUse` hook
reading that file can hard-stop the model until the chain runs.

The layer stack remains four deep, but Layer 2 is now
deterministic rather than advisory:

- **L1**: orchestrator coordinates Claude + codex + gemini
  verdicts (Sprint 15-A).
- **L2**: consensus-needed marker + consensus-gate hook (**this
  release**). Replaces the prose-invoke that didn't work for
  forked subagents.
- **L3**: phase-scoped `consensus.<phase>.approved` exit criteria,
  still gating `/vibeflow:advance` (Sprint 15-C).
- **L4**: arbiter + apply-arbiter-patch (Sprint 15-F/G).

## Added

- **`hooks/scripts/consensus-gate.sh`** — PreToolUse hook on
  `Bash|Write|Edit`. Reads `.vibeflow/state/consensus-needed.json`;
  if present, exits 2 with a stderr message naming `artifact` and
  `requiredCommand`. Fail-safe allows on missing jq / empty
  stdin / missing marker. Pass-through allows for writes under
  `.vibeflow/**`, `vibeflow:consensus-*` / `vibeflow:apply-arbiter-*`
  commands, and `rm`-ing the marker. Bypass for one call:
  `VF_SKIP_CONSENSUS_GATE=1`.

- **Marker write on 6 analysis skills**. The Final Step block now
  Writes `consensus-needed.json` with
  `{artifact, requiredCommand, createdAt, createdBy}` before any
  prose about invoking the orchestrator. Prose stays as
  best-effort for the main-agent case.

- **Marker drain on orchestrator + arbiter + apply**. Orchestrator
  drains on every terminal verdict status (APPROVED /
  NEEDS_REVISION / REJECTED). Arbiter and apply drain
  unconditionally at the end of their successful run — covers
  direct operator invocation of either skill without the
  orchestrator upstream.

- **`tests/integration/sprint-16.sh`** — 77 assertions pinning
  every behaviour above.

- **`docs/CONSENSUS-FLOW.md` "Layer 2 in detail" section** —
  documents the marker mechanism, the hook pass-throughs, who
  drains, and why the marker is necessary.

## Fixed

- **Skills never actually triggered consensus.** Before 2.4.0,
  analysis skills ended with a prose instruction to invoke
  `/vibeflow:consensus-orchestrator`. In practice Claude would
  finish the skill's output and move on — the orchestrator
  never ran, `.vibeflow/state/consensus/` stayed empty,
  `/vibeflow:advance` blocked with no visible cause. Addressed
  with the marker + hook chain above.

## Upgrade notes

- **Existing sessions**: if a stale
  `.vibeflow/state/consensus-needed.json` remains from a pre-2.4.0
  run, delete it manually. No migration script needed — the file
  either exists and points at a real artifact or doesn't.
- **`VF_SKIP_AUTO_CONSENSUS=1`** continues to skip Layer 2
  (marker-writing). `VF_SKIP_CONSENSUS_GATE=1` is new and bypasses
  the hook for one tool call. Neither overrides the phase-gate
  (Layer 3).
- **Tests**: run `bash hooks/tests/run.sh` and
  `bash tests/integration/sprint-16.sh` to confirm the new layer
  is live on your checkout.

## Backward compatibility

- The `Final Step: Auto-Consensus` header on each of the 6
  analysis skills is preserved, so Sprint 15-B harness assertions
  still pass.
- The orchestrator still drains `review-pending.json` (old marker
  from Sprint 15-D's post-commit flow). Both markers are drained
  in the same block.
- Skills that don't opt into marker-writing (everything outside
  the 6 L1 analyzers) are unaffected — the hook only triggers
  when the marker is present, and nothing else writes it.
