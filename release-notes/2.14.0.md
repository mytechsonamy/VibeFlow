# VibeFlow v2.14.0 — TESTING→DEPLOYMENT Consumer Hardening

**Sprint 26.** Tracing a real consumer's (FlowBridge) DEVELOPMENT →
TESTING → DEPLOYMENT path surfaced two boundary gaps and two
consensus-CLI robustness bugs. v2.14.0 closes all four.

## The release gate is now real (S26-A / S26-B)

- **`release.decision.go` is recorded.** `release-decision-engine` now
  auto-satisfies `release.decision.go` **on a GO verdict only**
  (CONDITIONAL/BLOCKED leave it unsatisfied). The release decision flows
  into `project.json`, `/vibeflow:status`, and the loop-audit — before,
  it was computed and thrown away.
- **Opt-in entry-gate.** New `gates.enforceEntryCriteria` (default
  **off**) makes `/vibeflow:advance` also require the target phase's
  `entryCriteria`. Turn it on and DEPLOYMENT can't be entered without a
  recorded GO. Off by default ⇒ existing advances are unchanged.

## Two FlowBridge-surfaced consensus-CLI bugs (S26-F / S26-G)

Real dogfooding caught two ways `codex`/`gemini` consensus silently
failed:

- **macOS has no `timeout` (S26-F).** The orchestrator wrapped each CLI
  in `timeout 90 …`, but macOS ships neither `timeout` nor `gtimeout` —
  so every call failed `command not found` (rc 127) → every CLI recorded
  as `cli_error`/REJECTED → consensus could never use the external
  reviewers on stock macOS. New portable `vf_run_timeout` helper: prefers
  `timeout`, then `gtimeout`, else a pure-bash watchdog (returns 124 on
  its own kill, **and preserves the piped prompt** — a backgrounded
  command otherwise gets stdin from /dev/null, which would feed codex an
  empty prompt).
- **The codex argument form hangs (S26-G).** A documented example used
  `codex exec "$(cat …)"` — the argument form leaves stdin open, so
  `codex exec` blocks on stdin EOF and **hangs indefinitely** (a consumer
  hit 51-minute hangs). Fixed to the pipe form (`build_review_prompt |
  codex exec …`), which closes stdin, with an explicit warning.

## TESTING-phase clarity (S26-C / S26-D)

- A pipeline-contract harness + unit tests pin the TESTING + DEPLOYMENT
  entry/exit criteria and each analyzer's artifact + auto-satisfy + map,
  so the consumer path can't silently rot.
- New `docs/TESTING-READINESS.md` walks DEVELOPMENT → TESTING →
  DEPLOYMENT, including the **"empty `.vibeflow/artifacts/` in
  DEVELOPMENT is normal"** clarification (it fills in TESTING).

## Configuration

```jsonc
{ "gates": { "enforceEntryCriteria": false } }
```

Default off; turn on for a strict release gate. See
`docs/TESTING-READINESS.md` + `docs/PHASE-BOUNDARIES.md`.

## Upgrade

```
/plugin uninstall vibeflow@vibeflow
/plugin install vibeflow@vibeflow
/reload-plugins
```

macOS users: `brew install coreutils` gives `gtimeout` (the pure-bash
fallback works without it too). No config migration.
