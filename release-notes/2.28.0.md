# VibeFlow v2.28.0 — artifacts are archived before they're rewritten

When a consensus round rewrites your PRD (or design spec, or architecture doc),
you want the prior version kept — not just for rollback, but as a durable record
of how the document evolved. v2.20.1 already snapshotted for *rollback*; this
adds the *version trail*.

## Added: `.vibeflow/archive/` before every edit

`apply-arbiter-patch` is the single point where a framework-driven rewrite
touches the PRD (the `prd-rewriter` specialist is diff-first and never writes
the document directly). As of v2.28.0, the **first** thing it does — *before*
the `git apply` — is copy each target file to a persistent, timestamped archive:

```
.vibeflow/archive/docs/PRD.md.2026-06-08T01-24-00Z.bak
```

- **Persistent + timestamped** — one entry per update, never cleaned up. It
  answers "what did the PRD look like before round 2?" — a clean version trail.
- **Discoverable** — `ls .vibeflow/archive/docs/` shows every prior version.
- **Distinct from rollback** — the session snapshot at
  `.vibeflow/state/arbiter-backups/<session>/` stays for one-command revert of
  *this* apply (`cp -R …/<session>/. .`). The archive is for *history*; the
  snapshot is for *undo*.
- **Covers all artifacts** — same step archives the design spec, architecture
  doc, ADRs — anything a patch targets — since they all update through this one
  skill.

So the order is now: confirm → **archive to `.vibeflow/archive/`** + snapshot for
rollback → `git apply`. Nothing is rewritten without a prior copy on disk.

Pinned by `tests/integration/sprint-40.sh` (static checks + a runtime probe that
the archive bash writes a timestamped, content-preserving copy under
`.vibeflow/archive/`).
